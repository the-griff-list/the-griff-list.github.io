# Admin security: authenticator MFA

The admin dashboard now supports Supabase Authenticator (TOTP) enrollment and a verification challenge at sign-in. Use an authenticator app rather than SMS where possible.

## Enable MFA

1. Open `admin.html` and sign in with the existing admin account.
2. Expand **Security · Authenticator Verification**.
3. Choose **Set Up Authenticator**.
4. Scan the QR code with an authenticator app, or enter the manual setup key.
5. Enter the current six-digit code to complete enrollment.
6. Keep the authenticator protected and ensure you have a secure recovery path through your authenticator provider.

The dashboard will require a current authenticator code on subsequent sign-ins once a factor is enrolled.

## Enforce MFA in the database

After enrollment succeeds, apply `confirmed-donation-wall.sql` if that table is not already present, then apply `admin-mfa-enforcement.sql` in the Supabase SQL Editor. This adds restrictive RLS policies requiring the designated admin's JWT to have `aal2` for the sensitive admin tables. Existing table-specific RLS policies remain responsible for the actual row permissions.

Do not apply the enforcement migration before the admin account has a verified TOTP factor, or the admin may be locked out of these tables.

## Security notes

- TOTP is generated by an authenticator app; the website does not store the shared secret in its own database.
- The QR code and manual setup key are displayed only during enrollment. Do not screenshot, share, or send the setup key to anyone.
- Supabase MFA does not provide recovery codes in the current documented API. Keep a secure backup factor/device and test account recovery before relying on MFA as the only second factor.
- MFA in the browser is not sufficient on its own; the database enforcement migration is required to protect direct API calls.
- The MFA interface and SQL migration are authored but have not yet been tested against the live Supabase project.
