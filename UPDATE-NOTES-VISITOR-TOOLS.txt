IMPORTANT SETUP
1. Back up the existing repository.
2. Read grifflist-next-update.sql and verify the admin UUID in its RLS policies matches the correct admin account before running it in Supabase SQL Editor.
3. Apply the SQL migration before publishing the new scripts. It adds a tracking_token column and a status RPC; existing request rows remain unchanged.
4. Upload the extracted website files to the repository root, preserving the existing Supabase configuration and assets.
5. Test song requests, status lookup, pinning, favourites and admin controls before using them at a show.
6. Configure the self-hosted MediaMTX server, HTTPS, WHIP/WHEP URLs and CORS/firewall settings separately. Audio-only mode requires the streaming server to accept an audio-only WHEP session.

LIMITATIONS
- The stream health display is a basic browser-side indicator, not a full bitrate or server monitoring dashboard.
- Automatic show reset starts a new show session timestamp and makes the “This Show” favourites range start fresh. It does not reset the all-time or monthly counts.
- Sound effects are reused from the homepage, but a browser or in-app browser may suppress audio until a user interaction.
- No live Supabase project or actual camera broadcast was available for end-to-end verification. Test in a staging copy first.
